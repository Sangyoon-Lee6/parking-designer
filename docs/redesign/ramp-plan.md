# 램프를 모듈로 조립하기 — 직선·90° 회전 모듈과 자동 경사 (2026-11-23)

상윤 님, 램프 단계 계획이에요. 램프를 평면 안팎 어디로든 끌어 옮기고, 직선 모듈과 90° 회전 모듈을 더하거나 빼서 모양을 잡게 해요. 그러면 프로그램이 층고에 맞춰 모듈마다 경사를 나누고, 3D에 실제 경사로 그려요.

먼저 분명히 할 점이 있어요. **"AI가 경사를 적용"하는 부분은 학습형 AI가 아니라 정해진 규칙으로 계산하는 자동 계산이에요.** 같은 램프를 넣으면 늘 같은 경사가 나오고, 근거는 주차장법 시행규칙이에요(3장).

## 0. 먼저 알아 둘 점

- 화면에 보이는 **r265는 GitHub(최신 r255, 2026-11-21)에도, 노트북에도 없어요.** 그래서 이 계획은 **r255 코드**와 단지형 시험본(r255 + "차로 먼저" 수정)을 기준으로 짰어요.
- 아래의 함수 이름과 줄 번호는 모두 **r255 기준**이에요. r265에서는 위치나 이름이 바뀌었을 수 있어서, 프롬프트마다 "줄 번호 말고 함수 이름으로 찾고, 없으면 같은 일을 하는 곳을 찾아라"라고 적어 두었어요.
- r255에는 단계가 3개(조건·평면·결과)뿐이에요. 상윤 님 화면의 **"5단계 램프"는 r265에서 생긴 것으로 보고**, 프롬프트는 "램프 단계(없으면 평면 단계의 램프 편집)"로 적었어요.
- r255에서는 저장·불러오기(localStorage 등) 코드를 찾지 못했어요. 그래도 예전 형식 램프를 새 형식으로 바꾸는 함수(`migrateLegacy`)를 넣어서, 배치안·예시·저장 파일 어디서 오든 예전 램프가 그대로 동작하게 했어요.
- 캐시 태그는 이전 계획(v266~v269) 다음인 **v270~v274**를 써요.

## 1. 지금 램프 코드가 하는 일과 한계 (r255)

### 1-1. 데이터
- `state.ramps`는 배열이지만 **실제로는 `ramps[0]` 하나만 써요.** (`state.js` `placeRamp()`는 `state.ramps = [ramp]`로 덮어쓰고, `refreshVariants()`·`layoutCore()`도 첫 번째만 봐요.)
- 램프 한 개는 `{ id, edge, t, width, length, placement, inset/offset }`예요.
  - `edge`(동서남북 중 한 변)와 `t`(그 변을 따라 잰 중심 위치)로만 자리를 정해요. **램프는 항상 외벽 한 변에 직각으로 붙어요.**
  - `placement`는 `"internal"`이나 `"external"` 중 하나이고, 한 램프가 둘 다일 수는 없어요(벽을 걸칠 수 없음).
  - 길이는 사용자가 정하지 않아요. `minStraightRampLength()`(121)가 층고로 계산하고, 화면의 길이 칸은 `readonly`예요.

### 1-2. 모양 (`layout.js`)
- `rampShape()`(219) → `rampShapeRaw()`(222)
  - 외부형은 항상 직선 사각형 하나예요.
  - 내부형은 직선이 반대쪽 벽 앞까지 들어가면 직선이에요. 깊이가 모자라면 **정해진 모양 하나**(직선 → 90° 곡선(내변 6m, 폭 6.5m) → 직선)로 자동으로 꺾어요. 꺾는 방향도 평면 가운데 쪽으로 고정이에요.
  - 곡선은 `arcSectors()`로 사각형 3개를 덮어 충돌 검사에 써요.
- `rampFootprint()`(419)는 바깥 사각형, `rampTopLip()`(433)은 아래층 진입 경계, `innerLip()`(2573)은 도착 경계예요.
- 경사는 `straightSegments()`가 [윗부분 완화 8.5% → 본 경사 17% → 아랫부분 완화 8.5%]로 나눠요.
  - 곡선 램프는 첫 직선을 17%로 다 쓰고, 곡선 14%, 남은 높이를 곡선 뒤 직선에 몰아요(`ease`로 비율 낮춤).
- `rampTransitions()`(103)가 완화구간 길이를 정해요. 지상 층은 max(도로변 3m, 50대 이상 1.7m), 100대 이상은 아랫부분 2m예요.

### 1-3. 배치 엔진이 램프를 다루는 방법
- `layoutCore()`(1119)
  - 내부형이면 `withArrivalZone()`(453)으로 램프 + **도착 앞 6m**를 코어가 피할 사각형으로 써요.
  - `rampPieces`를 `fixedBlocks`(1275)에 넣어 칸이 못 들어가게 해요.
  - `approachAisle()`(2097)과 `rampEntryAisle()`(2089)로 램프 끝에 차로를 붙여요.
- 검사 함수
  - `portalIssues()`(2590): 도착 경계와 진입 경계가 큰 차로 묶음에 닿는지 봐요.
  - `slopeIssues()`(2636): 17%를 넘는지 봐요.
  - `siteIssues()`(2676)·`rampOutside()`: 대지 여유 밖으로 나가는지 봐요.
  - `roadIssues()`: 도로 쪽 변인지 봐요.
- 외곽 기둥 띠 처리: `withGap()`(3273)이 램프 좌표를 안쪽 판으로 옮겨요(`t - c`).

### 1-4. 화면
- 평면 `plan.js`
  - `hitRamp()`(391)로 램프를 집어요.
  - 끌기(`drag.mode === "ramp"`, 231~289)는 `pickEdge`로 **가장 가까운 변**을 고르고 그 변을 따라서만 움직여요(`moveRamp(id, edge, t, offset)`).
  - 내부형만 벽에서 떨어뜨릴 수 있어요(`offset`).
- 3D `scene.js`
  - `addRamp()`(316): 직선은 네 꼭짓점 경사면 하나예요.
  - `addCurvedRamp()`(589): 중심선 `path[].h`를 따라 면을 펼쳐요.
  - `addRampEdges()`: 연석과 벽, `addGroundApproach()`: 지상 진입부, `rampHoles()`·`curvedRampHoles()`: 슬래브 구멍.
- 도면 `sheet.js` `slopePercent()`: 경사 % 표시.

### 1-5. 한계 정리
1. 램프 모양을 사용자가 정할 수 없어요. 직선 하나, 또는 직선+곡선+직선 하나로 프로그램이 정해요.
2. 위치는 외벽 한 변에 직각으로만 놓을 수 있어요. 평면 가운데, 비스듬한 방향, 벽을 걸치는 자리에는 못 둬요.
3. 지하가 여러 층이면 같은 모양을 쌓는 것만 돼요. 나선형은 없어요.
4. 경사 배분이 "앞에서부터 한도까지 쓰고 나머지를 뒤에 몬다"는 방식이에요. 구간마다 경사가 들쭉날쭉해요(예: 17% → 14% → 16.6%).
5. 내부형 도착 경계와 진입 경계가 `edge`를 기준으로 하드코딩돼 있어요(`rampTopLipRaw`, `innerLip`, `withArrivalZone`의 `if (ramp.edge === ...)`).
6. `withArrivalZone()`은 직선 램프에만 6m를 붙여요(`kind !== "straight"`이면 그대로 반환).

## 2. 새 모델: 모듈 사슬

### 2-1. 데이터
```js
ramp = {
  id, x, y,            // 시작점 = 램프 윗부분(지상 쪽) 중심선. 평면 좌표(m), 평면 밖이어도 됨
  heading,             // 내려가는 방향(도). 0=동, 90=북, 180=서, 270=남. 90° 단위로 회전
  width,               // 전 구간 폭. 회전 모듈이 있으면 6.5m 이상(50대 이상)
  innerRadius,         // 회전 모듈 기본 내변반경(6m)
  levels,              // 몇 개 층을 내려가는지(지하 층수)
  mode,                // "repeat" = 같은 사슬을 층마다 같은 자리에 쌓음 / "spiral" = 한 바퀴가 한 층
  modules: [
    { type: "straight", length },          // 0.5m 단위
    { type: "turn", dir: "L" | "R", radius }// 90°, 반경 = 내변반경(차로 안쪽 가장자리)
  ],
}
```
- 사슬을 따라가며 모듈마다 시작 자세와 끝 자세(점 + 방향)를 계산해요(`buildChain`).
  - 직선은 사각형 하나예요.
  - 회전은 1/4 원환이에요. 중심선 반경 Rc = 내변반경 + 폭/2이고, 길이 = π/2·Rc예요. 내변 6m, 폭 6.5m이면 Rc 9.25m, 길이 14.53m예요.
  - 충돌용 사각형은 기존 `arcSectors()`처럼 3개를 써요.
- 시작점, 방향, 평면 안/밖이 모두 자유예요.
  - 사슬 전체가 평면 밖이면 **외부 램프**예요. 칸을 잡아먹지 않고, 끝이 외벽에 닿아 있어야 해요.
  - 전체가 평면 안이면 **내부 램프**예요. 평면 안 부분이 배치 엔진의 장애물이 돼요.
  - 일부만 안이면 **걸침**이에요. 중심선이 외벽을 지나는 점을 찾아 그 자리에 벽 개구부(edge, t, 폭)를 만들어요.

### 2-2. 양끝 6m 구역 (칸 금지, 차로는 허용)
- **도착 구역**: 끝 자세 앞 6m예요. 평면 밖에서 끝나는 외부 램프는 외벽에서 안쪽으로 6m를 잡아요.
- **진입 구역**: 시작점이 평면 안이면 시작 자세 뒤 6m예요. 아래층에서 이 램프로 다시 들어가는 자리예요.
- **나선 착지 구역**: 나선의 첫 직선(착지부, 경사 0%) 옆 6m 중 평면 쪽이에요.
- 이 구역들은 **칸과 코어는 못 들어가고, 차로는 지나가야 해요.** 엔진은 구역마다 큰 차로 묶음에 닿는지 확인해요. 기존 `innerLip`과 `rampTopLip` 검사를 이것으로 바꿔요.

### 2-3. 평면 화면 조작
- 램프 몸체를 끌면 **사슬 전체가 평행 이동**해요. 평면 안팎을 가리지 않고 대지 여유 안이면 어디든 돼요. 0.5m 단위로 맞추고, 옵션을 켜면 기둥 격자선에 맞춰요.
- 회전 버튼(또는 R 키)을 누르면 시작점을 중심으로 90°씩 돌아요.
- 모듈을 클릭하면 선택돼요. **+직선**, **+90° 좌**, **+90° 우** 버튼은 선택한 모듈 뒤에 끼우고, 선택이 없으면 끝에 붙여요. **삭제**는 선택한 모듈을 지워요. 직선 모듈은 길이를 숫자로 입력해요(0.5m 단위).
- 층수와 방식(반복/나선)을 고를 수 있어요. **자동 맞춤** 버튼은 길이가 모자랄 때 가장 긴 직선을 늘려요.
- 바로바로 보여 주는 것:
  - 모듈마다 경사 %를 색으로 칠해요(초록 0% → 노랑 8.5% → 빨강 17%).
  - 동·코어와 겹침, 내변반경 미달, 폭 미달, 자기 겹침, 외벽 연결 실패, 6m 구역 막힘을 빨간 테두리와 문구로 알려요.
  - 길이가 모자라면 "직선 3.5m를 더하거나 90° 회전 1개를 더하세요"처럼 알려요.

### 2-4. 자동 경사 배분 (규칙 기반)
층마다 하는 일은 이래요.
1. 그 층에서 내려갈 구간을 정해요. 반복 방식은 사슬 전체, 나선 방식은 착지부를 뺀 나머지예요.
2. 구간 앞 `top` m와 뒤 `bottom` m를 완화구간으로 떼요.
   - 지상→B1: top = max(도로변 3m, 50대 이상이면 1.7m), bottom = 100대 이상이면 2m.
   - B1→B2 이하: top = 50대 이상이면 1.7m, bottom = 100대 이상이면 2m(도로와 안 닿음).
3. 완화구간 경계와 모듈 경계로 조각을 나누고, 조각마다 한도를 정해요.

   | 조각 | 직선 모듈 | 회전 모듈 |
   |---|---|---|
   | 본 경사 | 17% | 14% |
   | 완화구간·도로변 3m | 8.5% | 7% |

4. **최대 낙차 C = Σ(조각 길이 × 한도)**를 구해요.
   - C ≥ 층고이면 모든 조각에 같은 비율 k = 층고 / C를 곱해요. 그러면 한도를 넘지 않으면서 가장 완만하고 고른 경사가 돼요.
   - C < 층고이면 **부족**이에요. 모자란 높이 ΔH를 직선 ΔH/17%(0.5m 단위 올림)로 늘리는 방법과, 회전 ⌈ΔH/(회전 길이×14%)⌉개를 더하는 방법을 함께 알려 줘요.
5. 회전 모듈 경사는 **중심선 기준**으로 판정해요(기존 `rampShapeRaw`와 같음). 안쪽 가장자리는 Rc/Ri배 더 가팔라서 정보로만 보여 줘요(확인 필요, 3-1).

### 2-5. 여러 층
- **반복(repeat)**: 같은 사슬이 층마다 같은 자리에 겹쳐요(지금 앱과 같은 방식). 위아래 램프 사이 높이는 늘 층고와 같아요.
  - 층에 도착한 차는 도착 구역으로 나와서 순환 차로를 돌아 진입 구역으로 들어가요.
  - 그래서 내부 반복형은 **진입 구역과 도착 구역이 모두 평면 안**에 있어야 해요.
- **나선(spiral)**: 사슬이 닫힌 한 바퀴여야 해요(끝 자세 = 시작 자세). 예: [직선 6, 좌, 좌, 직선 6, 좌, 좌].
  - 첫 직선은 0% 착지부예요. 그 층 바닥과 옆으로 이어져요.
  - 나머지가 층고 하나를 내려가고, 한 바퀴 돌 때마다 한 층이에요.
  - 층마다 착지부 앞뒤에 완화구간을 둬요(보수적으로 잡은 값).
  - 착지부 쪽 벽은 3D에서 세우지 않아요.

### 2-6. 배치 엔진에 넘기는 것 (`analyzeOnPlate`)
- `block`: 평면 안에 있는 모듈 사각형(회전은 3개)이에요. 칸, 코어, 차로 모두 못 들어가요.
- `keepClear`: 6m 구역이에요. 칸과 코어는 못 들어가고, 차로는 들어갈 수 있어요.
- `openings`: 외벽 연결점(edge, t, 폭)이에요. 외부형과 걸침의 벽 개구부, 외부 나선의 착지부예요.
- `issues`: 2-3의 검사 결과예요.

### 2-7. 예전 램프 옮기기 (`migrateLegacy`)
- 외부형 `{edge, t, length}`는 외벽 밖 `length` m에서 시작해서 외벽으로 들어오는 직선 하나가 돼요.
- 내부 직선은 벽에서 `inset`(기본 11.2m) 안쪽에서 시작하는 직선 하나가 돼요.
- 내부 곡선(`rampShape().kind === "curved"`)은 [첫 직선, 회전(방향은 `shape.turn`과 변으로 계산), 곡선 뒤 직선]이 돼요.
- 원래 값은 `ramp.legacy`에 남겨요. 사슬이 예전과 같은 모양이면 엔진은 **예전 경로를 그대로** 써요. 그래서 report.mjs 기준 대수가 그대로 유지돼요.

### 3-1. 앱에서 정한 해석 (확인 필요)
1. **완화구간과 본 경사의 경계**: 17%에서 8.5%로 바뀌면 차이가 정확히 8.5%예요. 비고 문구("8.5% 이상 감소")를 글자 그대로 읽으면 이 경계도 볼록형 부분이 될 수 있어요. 실무와 지금 앱은 "1.7m를 8.5%로 두면 충족"으로 보고 있어서 그대로 따랐어요. 인허가 담당자 확인이 필요해요.
2. **직선 17%에서 곡선 14%로 바뀌는 곳**은 차이가 3%라 완화구간이 필요 없다고 봤어요(비고 기준).

5. **나선의 층마다 완화구간**: 법에서 직접 정한 게 아니라, 착지부(0%)와 경사 사이가 볼록형·오목형이 되므로 보수적으로 넣었어요.
6. **내변반경 5m 완화**: "주차대수 50대 이하"일 때만 5m로 했어요(조문 그대로).
